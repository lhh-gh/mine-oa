# MineAdmin OA 系统 — 用户需求梳理文档（D1）

> 项目代号：MineOA
> 技术基线：MineAdmin 3.2（基于 Hyperf 3.x，PHP 8.2+）｜移动端：unibest（uni-app 工程模板）
> 版本：v0.3（修订稿：合入 D5 两轮复审意见；锁定 MineAdmin 3.2、移动端选型 unibest）
> 日期：2026-10-26

---

## 1. 项目背景与业务目标

### 1.1 背景

中小企业（目标规模 ≤ 500 人）日常办公依赖口头沟通、纸质单据或零散的微信群审批，
存在审批进度不透明、考勤统计困难、公告触达率低、文档版本混乱等问题。

### 1.2 业务目标

| 编号 | 目标 | 衡量指标 |
| --- | --- | --- |
| G1 | 审批全流程线上化 | 常用审批（请假/报销/采购/用章）100% 线上流转，平均审批耗时下降 50% |
| G2 | 考勤自动化 | 打卡、补卡、统计报表自动生成，HR 月度统计工时从 2 天降至 0.5 天 |
| G3 | 信息触达可量化 | 公告已读率可统计，重要公告触达率 ≥ 95% |
| G4 | 文档集中管理 | 部门文档统一存储、权限受控、可检索 |

### 1.3 非目标（本期不做）

- 复杂 BPMN 流程引擎（条件分支、并行会签**移至二期/三阶段**，见 §6 分期计划）
- 薪资核算、绩效管理（与考勤联动，二期再评估）
- 跨日排班、多段班次、半天粒度请假（一期考勤限定固定白班，见 §2.3）

## 2. 功能清单

### 2.1 复用 MineAdmin 内置能力（不重复开发）

| 模块 | 说明 |
| --- | --- |
| 用户管理 | 员工账号（`user` 表，以 `user_type` 字段区分用户类别）、部门归属、岗位 |
| RBAC 权限 | 角色、菜单权限、注解级 API 权限（`#[Permission]`）、数据权限（按部门隔离） |
| 部门负责人 | 复用内置 `dept_leader` 关联（部门 N:N 负责人），用于审批人解析 |
| 操作日志 | 后台操作审计 |
| 附件上传 | 本地/OSS 存储驱动（文档中心在其上扩展） |

> 复用字段名以开工时锁定的 MineAdmin 具体版本源码为准（D5 P2-1）；
> v3 官方文档显示用户类别字段为 `user_type`（枚举，如 `Type::SYSTEM`），不是 `type`。

### 2.2 核心办公（审批流）—【核心】

**业务单据与通用审批双层结构**（D5 P1-2）：请假/报销/采购/用章为结构化业务单据
（固定字段落库、可索引可校验），通用审批实例承载流转与留痕；动态表单仅承载附加说明字段。

| 功能 | 要点 | 阶段 |
| --- | --- | --- |
| 审批模板配置 | 管理员配置：模板名称、关联业务单据类型、**顺序审批节点序列**、抄送人规则 | 一阶段 |
| 发起审批 | 员工填写业务单据（如请假：假别/起止/时长）+ 附加说明发起 | 一阶段（请假） |
| 审批操作 | 同意 / 驳回（驳回至发起人或终止，按模板配置）/ 转交 / 撤回（**首个节点未处理前**） | 一阶段 |
| 审批提醒 | 待办产生时站内消息 + 角标（推送通道策略见 §2.5） | 一阶段 |
| 审批记录 | 每一步操作留痕：操作人、时间、意见、耗时、**审批轮次**（驳回重提累计） | 一阶段 |
| 我的申请 / 待我审批 / 我已审批 / 抄送我的 | 四个常用视图 | 一阶段 |
| 报销 / 采购 / 用章单据 | 各自独立单据表与校验（金额明细、票据附件、用印类型等） | 三阶段 |
| 并行会签节点 | 节点内多人全部通过才前进 | 二期（三阶段落地） |

### 2.3 考勤签到 —【核心】

**一期限定**（D5 P1-3）：固定白班 + 单段工作时间 + 午休扣除；半天请假、跨日班次不支持。

| 功能 | 要点 | 阶段 |
| --- | --- | --- |
| 打卡 | H5 端上班/下班打卡；支持 IP 范围校验（地理位置围栏默认不启用，隐私合规，见 §6.2） | 二阶段 |
| 考勤日历 | 个人出勤日历：正常/迟到/早退/缺卡/请假/节假日；展示口径分"历史已结算 / 当日暂计 / 未来未发生" | 二阶段 |
| 补卡申请 | 走审批流模板，通过后自动修正考勤记录（日结重算） | 二阶段 |
| 排班与规则 | 工作日历（默认双休）、上下班时间、午休时段、迟到早退阈值、**规则生效日期**可配置 | 二阶段 |
| 月度报表 | 按部门/个人统计：出勤天数、迟到次数、缺卡次数；支持导出 Excel | 二阶段 |
| 数据联动 | 请假审批通过后经事件表（Outbox）可靠写入考勤记录 | 二阶段 |

### 2.4 公告与文档中心 —【核心】

| 功能 | 要点 | 阶段 |
| --- | --- | --- |
| 公告发布 | 富文本公告（服务端 XSS 过滤），支持置顶、指定部门范围 | 三阶段 |
| 已读统计 | 每篇公告的已读/未读人员列表，未读可一键催办 | 三阶段 |
| 站内消息中心 | 统一消息盒子：审批待办、公告、系统通知；未读角标 | 一阶段 |
| 文档中心 | 目录树（按部门/类别）、上传下载、在线预览（Office 转 PDF）、权限受控；**H5 提供只读访问** | 三阶段 |

### 2.5 移动端（H5 + 小程序）—【核心】

采用 **unibest**（uni-app 最佳实践工程模板：uni-app + Vue3 + TypeScript + Vite5 + Pinia + UnoCSS + wot-design-uni）
一套代码编译 H5 与微信小程序两端，审批核心功能双端一致：

| 能力 | H5 端 | 小程序端 |
| --- | --- | --- |
| 审批待办 / 发起 / 处理 | ✅ | ✅ |
| 打卡与考勤日历 | ✅ | ✅ |
| 公告阅读与消息中心 | ✅ | ✅ |
| 登录方式 | 账号密码 + 手机验证码 | 微信授权登录（code2session 绑定员工账号，首次绑定需手机号校验） |
| 消息提醒 | 站内消息 + 角标 | 订阅消息（Subscribe Message）推送审批待办提醒 |

> 小程序端一期承担**审批 + 考勤 + 公告阅读**三块高频能力，文档中心、后台管理类操作不进小程序
> （保持轻量，降低审核与维护成本）。文档中心在 H5 端提供**只读**（浏览/下载/预览）。

**推送触达策略（修订）**：

- **浏览器 Web Push 一期移除**：H5 的主要运行环境是微信内置浏览器与国内手机浏览器，
  均不支持或不可达 Web Push 所依赖的 Service Worker / 推送服务。H5 一期提醒通道仅
  **站内消息 + 角标**（下拉刷新可见）。
- **小程序订阅消息为一次性授权**（每次授权仅可推一条），存在推送失败窗口：
  站内消息 + 角标为保底通道（默认可达，不承诺"必然触达"）。
- **企业微信应用消息**：受限于应用可见范围与平台频控（非"无限推送"），二期评估
  升级为主通道，微信小程序继续承担审批操作入口。
- **紧急审批短信提醒**：仅关键模板开关启用（运营成本高）。短信通道为一阶段登录链路的
  硬依赖，选型与报备见 D2 §1 与 §4 约束。

## 3. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 并发用户 ≤ 100；审批/打卡接口 P95 < 500ms；早高峰打卡无雪崩 |
| 可用性 | 工作日 8:00-20:00 可用性 ≥ 99.5%；单点部署 + 每日备份 |
| 安全 | JWT 鉴权；操作/审批全留痕；敏感数据（手机号）脱敏展示；上传文件类型白名单；富文本公告服务端 XSS 过滤；小程序服务端校验 code2session，禁止信任前端身份 |
| 兼容 | H5 适配主流手机浏览器与微信内置浏览器；小程序兼容微信基础库 ≥ 2.30 |
| 可维护 | 代码遵循 PSR-12；模块化目录（主工程 App 层 `App\OA\` 模块，非插件，见 D2 §2）；接口文档（Swagger）自动生成 |

## 4. 约束条件

- PHP ≥ 8.2，Swoole ≥ 5.0（MineAdmin 3.x 基线；开工前锁定具体 release）
- MySQL 8.0 + Redis 6+
- 审批流采用自研状态机（**一期顺序审批**，并行会签二期演进），不引入外部工作流引擎
- 单体模块化部署（Hyperf 单进程组，OA 直接开发在 MineAdmin 主工程 `App/OA/` 模块内，**不采用插件体系**），不拆微服务
- 移动端采用 **unibest**（uni-app + Vue3 + TS + Vite5 + Pinia + UnoCSS）工程模板：约定式路由、请求封装/拦截、登录拦截内置；pnpm 命令行构建 H5 与微信小程序（无需 HBuilderX；仅 App 端需要）；后端为两端提供同一套 Api 接口
- 前端：后台 Vue3 + Element Plus（MineAdmin 自带，OA 后台页面直接加入后台前端工程）；移动端 UI 库 **wot-design-uni**（为 uni-app 多端设计；Vant 不适配小程序端，已弃用原设想）
- **短信服务为一阶段硬依赖**（H5 验证码登录、小程序绑定校验）：采用云厂商短信（如阿里云/腾讯云），签名与模板需企业资质报备（审核周期 1~2 工作日，需提前办理），凭据走 `.env`

## 5. 验收标准（一期）

1. 管理员可配置一个「请假审批」模板并完成一次完整流转：发起 → 审批 → 归档，全程有留痕（后台与移动端均可操作）。
2. 任意员工可在 H5 或小程序完成打卡，HR 可导出当月考勤报表。
3. 公告发布后可查看已读名单，未读一键催办。
4. 请假审批通过后，考勤日历自动显示对应请假状态（经 Outbox 事件可靠联动）。
5. 权限验证：普通员工无法访问 HR 报表菜单（RBAC + 数据权限，OA 表列映射见 D2 §6.4）。
6. 小程序端：微信授权登录并绑定员工账号后，可收到审批待办订阅消息提醒并完成一次审批。
7. 请假单据时间重叠提交被正确拦截（业务单据校验）。
8. 并发场景：同一待办被两人同时处理，仅一人成功（乐观锁 + 实例级锁，见 D2 §3.1）。

## 6. 分期计划（对齐 D5 §3）与待评审问题

### 6.1 分期

| 阶段 | 范围 | 核心验收 |
| --- | --- | --- |
| 一阶段 | 员工登录（三端）、权限基线、固定请假单据、顺序审批、站内消息 | 完整走通一次请假；越权与重复提交被正确拦截 |
| 二阶段 | 固定白班打卡、补卡、请假-考勤联动（Outbox）、考勤月报 | 审批结果可靠影响考勤；补卡后可重算 |
| 三阶段 | 会签、公告、文档权限、报销/采购/用章业务单据 | 并发会签正确；业务单据权限完整 |
| 后续 | 可视化流程配置、复杂排班、Office 预览、企业微信通道 | 按需独立验收 |

### 6.2 待评审问题清单

- [ ] 打卡地理位置围栏：**建议一期不做**（仅 IP 段 + 时间窗校验），规避个人位置信息采集的合规成本；如需围栏（小程序定位能力已具备）再单独评审隐私告知文案
- [x] 公告"定时发布"：**调整为三阶段**（公告整体在三阶段，非一期必须）
- [x] 文档在线预览依赖 LibreOffice：**调整为三阶段**，作为独立组件按需部署
