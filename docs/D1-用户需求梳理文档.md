# MineAdmin OA 系统 — 用户需求梳理文档（D1）

> 项目代号：MineOA
> 技术基线：MineAdmin 3.2（基于 Hyperf 3.x，PHP 8.2+）｜移动端：unibest **v4.4.1**（以 mobile/package.json 为准）
> 版本：v0.5（按 D9 A01–A16 修订；设计契约已统一，业务实现与运行验收待完成）
> 日期：2026-10-26

---

## 1. 项目背景与业务目标

### 1.1 背景

中小企业（目标规模 ≤ 500 人）日常办公依赖口头沟通、纸质单据或零散的微信群审批，
存在审批进度不透明、考勤统计困难、公告触达率低、文档版本混乱等问题。

### 1.2 业务目标

| 编号 | 目标 | 衡量指标 |
| --- | --- | --- |
| G1 | 审批全流程线上化 | 常用审批（请假/报销/采购/用章）100% 线上流转，平均审批耗时下降 50% |
| G2 | 考勤自动化 | 打卡、补卡、统计报表自动生成，HR 月度统计工时从 2 天降至 0.5 天 |
| G3 | 信息触达可量化 | 公告已读率可统计，重要公告触达率 ≥ 95% |
| G4 | 文档集中管理 | 部门文档统一存储、权限受控、可检索 |

### 1.3 非目标（本期不做）

- 复杂 BPMN 流程引擎和条件分支；并行会签安排在三阶段，见 §6
- 薪资核算、绩效管理（后续独立评估）
- 跨日排班、多段班次、半天粒度请假（二阶段考勤限定固定白班，见 §2.3）

## 2. 功能清单

### 2.1 复用 MineAdmin 内置能力（不重复开发）

| 模块 | 说明 |
| --- | --- |
| 用户管理 | 内部员工复用 `user` 表的 SYSTEM(100) 账号；员工/审批人/HR 为业务角色，部门归属与岗位复用原模型 |
| RBAC 权限 | 角色、菜单权限、注解级 API 权限（`#[Permission]`）、数据权限（按部门隔离） |
| 部门负责人 | 复用内置 `dept_leader` 关联（部门 N:N 负责人），用于审批人解析 |
| 操作日志 | 后台操作审计 |
| 附件上传 | 本地/OSS 存储驱动（文档中心在其上扩展） |

**身份决策（D9 A04）**：内部员工统一使用 `App\Model\Enums\User\Type::SYSTEM`（100），
PC 沿用 MineAdmin 后台登录；移动端对同一账号签发 mobile 场景 JWT。SYSTEM 表示系统内账号，
不表示超级管理员；普通员工仅授予 OA 自助菜单及自身业务资源权限。`Type::USER`（200）保留为
外部用户类别，不按终端自动切换用户类别，也不建立一人两套员工账号。现有 USER(200) 数据如需纳入，
须先形成账号映射和人工核对清单，不通过种子脚本批量改类型。

员工可属于多个部门；OA 以生效日期内的唯一办公主部门作为发起部门和考勤归属，
历史通过 `oa_employee_department` 保存（D3 §3.5），不覆盖 MineAdmin 多部门关系。

### 2.2 核心办公（审批流）—【核心】

**业务单据与通用审批双层结构**（D5 P1-2）：请假/报销/采购/用章为结构化业务单据
（固定字段落库、可索引可校验），通用审批实例承载流转与留痕；动态表单仅承载附加说明字段。
一阶段请假时长使用带版本的固定工作日历配置并冻结计算依据，不依赖二阶段考勤管理页面和表。

| 功能 | 要点 | 阶段 |
| --- | --- | --- |
| 审批模板配置 | 管理员配置：模板名称、关联业务单据类型、**顺序审批节点序列**、抄送人规则 | 一阶段 |
| 发起审批 | 员工填写业务单据（如请假：假别/起止/时长）+ 附加说明发起 | 一阶段（请假） |
| 审批操作 | 同意 / 驳回（驳回至发起人或终止，按模板配置）/ 转交 / 撤回（**首个节点未处理前**） | 一阶段 |
| 审批提醒 | 待办产生时站内消息 + 角标（推送通道策略见 §2.5） | 一阶段 |
| 审批记录 | 每一步操作留痕：操作人、时间、意见、耗时、**审批轮次**（驳回重提累计） | 一阶段 |
| 我的申请 / 待我审批 / 我已审批 / 抄送我的 | 四个常用视图 | 一阶段 |
| 报销 / 采购 / 用章单据 | 各自独立单据表与校验（金额明细、票据附件、用印类型等） | 三阶段 |
| 并行会签节点 | 节点内多人全部通过才前进 | 三阶段 |

### 2.3 考勤签到 —【核心】

**二阶段范围限定**（D5 P1-3）：固定白班 + 单段工作时间 + 午休扣除；半天请假、跨日班次不支持。

| 功能 | 要点 | 阶段 |
| --- | --- | --- |
| 打卡 | H5 与小程序端上班/下班打卡；支持 IP 范围与时间窗校验（地理位置围栏不纳入前三阶段） | 二阶段 |
| 考勤日历 | 个人出勤日历：正常/迟到/早退/缺卡/请假/节假日；展示口径分"历史已结算 / 当日暂计 / 未来未发生" | 二阶段 |
| 补卡申请 | 走审批流模板，通过后自动修正考勤记录（日结重算） | 二阶段 |
| 排班与规则 | 工作日历（默认双休）、上下班时间、午休时段、迟到早退阈值、**规则版本与适用部门的生效区间**可配置 | 二阶段 |
| 月度报表 | 按部门/个人统计：出勤天数、迟到次数、缺卡次数；支持导出 Excel | 二阶段 |
| 数据联动 | 请假通过、补卡生效后经 Outbox 持久化投递与消费确认触发日结重算；原始打卡不覆盖 | 二阶段 |

### 2.4 公告与文档中心 —【核心】

| 功能 | 要点 | 阶段 |
| --- | --- | --- |
| 公告发布 | 富文本公告（服务端 XSS 过滤），支持置顶、指定部门范围 | 三阶段 |
| 已读统计 | 每篇公告的已读/未读人员列表，未读可一键催办 | 三阶段 |
| 站内消息中心 | 统一消息盒子：审批待办、公告、系统通知；未读角标 | 一阶段 |
| 文档中心 | 目录树（按部门/类别）、上传下载、原生 PDF 预览、权限受控；**H5 提供只读访问**；私有文件经授权下载，Office 转 PDF 预览为后续可选能力 | 三阶段 |

### 2.5 移动端（H5 + 小程序）—【核心】

采用 **unibest**（uni-app 最佳实践工程模板：uni-app + Vue3 + TypeScript + Vite5 + Pinia + UnoCSS + wot-design-uni）
工程主请求链为 `src/api → src/http/http.ts → src/http/interceptor.ts → uni.request`；
保留现有 token/user store 分工，接入双 token 与登录门禁（均待实现适配），不迁移 alova。
一套代码编译 H5 与微信小程序两端，审批核心功能双端一致：

| 能力 | H5 端 | 小程序端 |
| --- | --- | --- |
| 审批待办 / 发起 / 处理 | ✅ | ✅ |
| 打卡与考勤日历 | ✅ | ✅ |
| 公告阅读与消息中心 | ✅ | ✅ |
| 登录方式 | 账号密码 + 手机验证码 | 微信授权登录（code2session 绑定员工账号，首次绑定需手机号校验） |
| 消息提醒 | 站内消息 + 角标 | 一阶段站内消息+角标；三阶段增加订阅消息提醒 |

> 小程序一阶段承担审批与消息，二阶段增加考勤，三阶段增加公告及订阅推送；文档中心、后台管理类操作不进小程序
> （保持轻量，降低审核与维护成本）。文档中心在 H5 端提供**只读**（浏览/下载/预览）。

**推送触达策略（修订）**：

- **H5 提醒通道**：前三阶段以站内消息 + 角标为基线；Web Push 不纳入范围，避免依赖浏览器与推送服务的环境差异。
- **小程序订阅消息为一次性授权**（每次授权仅可推一条），存在推送失败窗口：
  站内消息 + 角标为保底通道（默认可达，不承诺"必然触达"）。
- **企业微信应用消息**：受限于应用可见范围与平台频控（非"无限推送"），后续评估
  升级为主通道，微信小程序继续承担审批操作入口。
- **紧急审批短信提醒**：作为后续模板级可选能力。短信验证码通道为一阶段登录链路的
  硬依赖，选型与报备见 D2 §1 与 §4 约束。

## 3. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 并发用户 ≤ 100；审批/打卡接口 P95 < 500ms；早高峰打卡无雪崩 |
| 可用性 | 工作日 8:00-20:00 可用性 ≥ 99.5%；单点部署 + 每日备份 |
| 安全 | JWT 鉴权；操作/审批全留痕；敏感数据（手机号）脱敏展示；上传文件类型白名单；富文本公告服务端 XSS 过滤；小程序服务端校验 code2session，禁止信任前端身份 |
| 兼容 | H5 适配主流手机浏览器与微信内置浏览器；小程序兼容微信基础库 ≥ 2.30 |
| 可维护 | 代码遵循 PSR-12；按 MineAdmin 3.2 实际分层组织（各层 `OA/` 子目录，非插件，见 D2 §2）；接口文档（Swagger）自动生成 |

## 4. 约束条件

- PHP ≥ 8.2，Swoole ≥ 5.0（MineAdmin 3.2 基线；具体组件版本以 composer.lock 为准）
- MySQL 8.0 + Redis 6+
- 审批流采用自研状态机（**一阶段顺序审批**，并行会签三阶段），不引入外部工作流引擎
- 单体模块化部署（Hyperf 单进程组，OA 按 MineAdmin 3.2 分层结构以各层 `OA/` 子目录开发在主工程内，**不采用插件体系**），不拆微服务
- 移动端采用 **unibest**（uni-app + Vue3 + TS + Vite5 + Pinia + UnoCSS）工程模板：约定式路由与请求封装已有基础，OA 双 token 与完整登录门禁按 D2/D8 接入；pnpm 命令行构建 H5 与微信小程序（本项目 H5/小程序不依赖 HBuilderX）；后端为两端提供同一套 Api 接口
- 前端：后台 Vue3 + Element Plus（MineAdmin 自带，OA 后台页面直接加入后台前端工程）；移动端 UI 库 **wot-design-uni**（为 uni-app 多端设计；Vant 不适配小程序端，已弃用原设想）
- **短信服务为一阶段硬依赖**（H5 验证码登录、小程序绑定校验）：采用云厂商短信（阿里云短信），签名与模板需企业资质报备（审核时长以服务商实际结果为准，需提前办理），凭据走 `.env`

## 5. 分阶段验收标准（与 §6、D6 一一对应）

| 编号 | 阶段 | 验收结果 |
| --- | --- | --- |
| AC1-01 | 一 | 同一内部员工可在 PC、H5、小程序登录；双 token 生命周期、首次微信绑定与退出契约一致 |
| AC1-02 | 一 | 管理员配置固定请假模板的顺序节点；员工发起、审批、归档全程可追踪 |
| AC1-03 | 一 | 回退至 DRAFT 可重新提交并增加轮次；终态 REJECTED 不允许原实例重提；旧表单值、单据与节点快照可还原 |
| AC1-04 | 一 | 并发及重复业务操作仅提交一次有效状态变更；抄送列表与接收人快照一致 |
| AC1-05 | 一 | 员工角色只具有自助权限；资源归属、模板发起范围、菜单权限与部门策略按 D2 生效 |
| AC1-06 | 一 | 站内消息通过持久化投递与消费去重产生；重启后可恢复未完成消费，无重复消息 |
| AC1-07 | 一 | 默认迁移可发现 OA 表，菜单能加载首个页面；两端构建与生产路径冒烟通过 |
| AC2-01 | 二 | H5/小程序打卡同步入库，重复请求返回已记录信息；HR 可按权限导出月报 |
| AC2-02 | 二 | 补卡及请假联动重算可追溯；原始打卡不覆盖，历史部门和规则版本保持稳定 |
| AC3-01 | 三 | 会签、报销/采购/用章、公告定时发布与已读统计分别验收 |
| AC3-02 | 三 | 私有文档的目录、上传和授权下载按权限交付；H5 只读、小程序不开放 |
| AC3-03 | 三 | 微信订阅消息按模板记录授权与投递结果，失败降级站内消息；不承诺每次必达 |

性能与可用性为交付目标，须在对应阶段实测，不因文档完成而视为达标。

## 6. 分期计划与范围边界

### 6.1 分期

| 阶段 | 范围 | 核心验收 |
| --- | --- | --- |
| 一阶段 | 同一员工三端登录、权限基线、固定请假单据、顺序审批、抄送、站内消息与持久化 Outbox 消费确认 | 完整走通一次请假；越权与重复提交被正确拦截 |
| 二阶段 | 固定白班打卡、补卡、请假-考勤联动（Outbox）、考勤月报 | 审批结果可靠影响考勤；补卡后可重算 |
| 三阶段 | 会签、公告、私有文档与 H5 只读、订阅推送、报销/采购/用章业务单据 | 并发会签正确；业务单据权限完整 |
| 后续 | 可视化流程配置、复杂排班、Office 预览、企业微信通道 | 按需独立验收 |

### 6.2 范围边界

- 地理位置围栏、跨日/多段班次、半天粒度请假不纳入前三阶段；后续另行需求设计。
- 一阶段表单为固定请假单据 + 有限附加字段配置；不承诺拖拽表单设计器或 BPMN 流程画布。
- 公告、订阅推送在三阶段；Office 转 PDF 与企业微信通道为后续可选项。
- D5 记录设计修订与实施门禁，D6 记录验证范围，D9 保留原始审计发现及整改追踪。
