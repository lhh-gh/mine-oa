## 1. 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 后端框架 | MineAdmin 3.x（Hyperf 3.x） | 自带 RBAC、菜单、日志、代码生成器；协程常驻内存，审批/打卡高并发友好 |
| 语言基线 | PHP 8.2+（类型声明、枚举、readonly） | MineAdmin 3.x 最低要求，严格类型 |
| 数据库 | MySQL 8.0 | 主存储；InnoDB 事务保证审批流转一致性 |
| 缓存/队列 | Redis 6+ | 缓存（权限/部门树）+ 异步队列（消息推送、报表生成） |
| 后台前端 | MineAdmin 自带 Vue3 + Element Plus | 零成本复用管理端 |
| 移动端 | uni-app（Vue3 + Pinia）编译 H5 与微信小程序 | 一套代码双端发布，审批/考勤/公告 UI 复用，维护成本减半 |
| 文档预览 | LibreOffice headless（Docker 部署，可选） | Office 转 PDF 在线预览 |
| 定时任务 | Hyperf Crontab（进程内） | 考勤日结、公告定时发布、月报生成 |

## 2. 分层架构与模块划分

单体模块化：一个 Hyperf 应用，业务按 `app/` 下的模块隔离，模块间只通过 Service 接口调用，
禁止跨模块直接操作他人 Model。

```
mineoa/
├── app/
│   ├── Api/            # 移动端接口（H5 与小程序共用同一套接口）
│   │   └── OA/         # 移动端专用：微信登录、订阅消息授权记录
│   └── Admin/          # 管理后台（MineAdmin 默认应用）
│       └── OA/                          # ---- OA 业务模块 ----
│           ├── Approval/                # 审批中心【核心】
│           │   ├── Controller/          # TemplateController, ProcessController...
│           │   ├── Service/             # TemplateService, ProcessService
│           │   ├── Model/               # ApprovalTemplate, ApprovalInstance...
│           │   ├── StateMachine/        # ★ 自研状态机（见 §4）
│           │   └── Form/                # 表单字段渲染器（后台+H5 复用 schema）
│           ├── Attendance/              # 考勤：打卡、日历、报表、日结 Job
│           ├── Announcement/            # 公告：发布、已读统计
│           ├── Document/                 # 文档中心：目录、权限、预览
│           └── Message/                  # 消息中心：站内信、角标、催办
├── config/
│   └── autoload/                        # 模块配置各自独立文件
├── crontab/                             # 定时任务定义
└── web/                                 # 前端（admin 后台 + h5 移动端）
```

**请求流转**：HTTP(Swoole 协程) → Middleware(JWT/权限) → Controller → Service(事务边界) → Model/StateMachine → MySQL/Redis。

## 3. 关键流程

### 3.1 审批流转（核心链路）

```
发起人提交 → 创建审批实例(状态=PENDING) → 生成节点任务队列
  → 当前节点审批人收到待办(队列异步推送消息)
  → 审批人操作(同意/驳回/转交)
      ├─ 同意: 节点内全部处理 → 前进到下一节点 → 无下一节点则归档(状态=APPROVED)
      ├─ 驳回: 按配置回退(发起人重新编辑 / 上一节点 / 终止)
      └─ 转交: 任务处理人变更，节点不前进
→ 状态变更 + 操作留痕写入(同一 DB 事务)
→ 触发后置动作(请假通过 → 写入考勤；队列解耦)
```

- **一致性**：实例状态变更、节点任务更新、操作日志三表同事务（`$db->transaction`）。
- **并发防重**：任务处理加乐观锁版本号 + Redis 分布式锁（`approval:task:{id}`），
  防止同一待办被重复点击处理（协程环境下必须防）。

### 3.2 移动端双端接入（H5 + 小程序）

**一套接口，双端复用**：`app/Api/OA` 提供统一 REST 接口，uni-app 端通过条件编译处理平台差异（登录、推送）。

```
登录鉴权（按端区分，Token 结构与权限体系完全一致）：
  H5      → 账号密码 / 手机验证码 → JWT
  小程序  → wx.login 获取 code
            → 服务端 code2session 换 openid（AppSecret 只存服务端 .env）
            → 首次登录绑定员工账号（openid ↔ user_id 落库 + 手机号校验）
            → 签发同一套 JWT
```

**安全要点**：身份一律以服务端 JWT 为准，禁止信任小程序端明文 openid/session_key；
`session_key` 不下发给前端。

**消息推送双通道**：
- H5：站内消息 + 浏览器 Web Push（可降级为角标）。
- 小程序：审批待办产生时通过队列异步调用微信「订阅消息」接口推送；
  用户在端上授权订阅后记录授权状态，未授权用户降级为站内消息 + 角标提醒。
  AppSecret、订阅消息模板 ID 均走 `.env` 配置。

### 3.3 考勤日结

打卡实时写入原始记录表 → Crontab 每日 00:30 日结：
对照排班生成考勤日记录（正常/迟到/缺卡/请假），报表只查日结表，避免实时聚合。

## 4. 自研审批状态机设计

用 PHP 8.1 **枚举 + 状态转移表**实现，纯内存计算、无外部依赖：

```php
<?php
// app/Admin/OA/Approval/StateMachine/ProcessStatus.php
// 审批实例状态枚举：所有合法状态集中定义，禁止魔法数字
enum ProcessStatus: int
{
    case DRAFT     = 1; // 草稿（发起人可撤回编辑）
    case PENDING   = 2; // 审批中
    case APPROVED  = 3; // 已通过（终态）
    case REJECTED  = 4; // 已驳回（终态或回退，按模板配置）
    case CANCELED  = 5; // 发起人撤回（终态）
}
```

```php
<?php
// app/Admin/OA/Approval/StateMachine/Transition.php
// 状态转移表：定义"当前状态 + 事件 => 目标状态"的全部合法路径
// 非法转移直接抛异常，保证流程不可被绕过（安全边界）
final class Transition
{
    /** @var array<string, ProcessStatus> key 格式: "当前状态:事件" */
    private const MAP = [
        'DRAFT:SUBMIT'     => ProcessStatus::PENDING,
        'DRAFT:CANCEL'     => ProcessStatus::CANCELED,
        'PENDING:APPROVE_ALL'  => ProcessStatus::APPROVED,   // 当前节点全部通过且为末节点
        'PENDING:REJECT_TO_START' => ProcessStatus::DRAFT,   // 驳回至发起人（可重新编辑）
        'PENDING:REJECT_END'    => ProcessStatus::REJECTED,  // 驳回终止
        'PENDING:CANCEL'    => ProcessStatus::CANCELED,      // 待首节点处理前可撤回
    ];

    public static function go(ProcessStatus $from, string $event): ProcessStatus
    {
        return self::MAP["{$from->name}:{$event}"]
            ?? throw new \DomainException("非法状态转移: {$from->name} + {$event}");
    }
}
```

**节点层状态**（实例内）：`WAIT(未到) → ACTIVE(当前待办) → PASSED/REJECTED(已处理)`；
并行会签节点 = 节点内多任务，全部 PASSED 才能触发 `APPROVE_ALL` 前进。
一期支持：顺序节点 + 并行会签 + 驳回策略两档，复杂条件路由留到二期。

## 5. 高并发决策（中小规模够用 + 留扩展位）

| 场景 | 策略 |
| --- | --- |
| 早高峰打卡 | 打卡写库走 Redis 队列异步落库；前端即返"打卡成功" |
| 部门树/权限 | Redis 缓存，TTL 5min + 修改后台主动失效 |
| 审批待办列表 | 待办数走 Redis 计数器，列表查库 |
| 审批待办推送 | 队列异步推送（H5 站内/Web Push + 小程序订阅消息），推送失败不阻塞主流程 |
| 报表导出 | 大数据量报表队列生成文件 + 站内信通知下载链接 |
| 缓存防护 | Key 规范 `mineoa:{module}:{biz}:{id}`；热 key 无雪崩风险（TTL 加随机抖动） |

## 6. 可观测性与错误处理（前置设计）

- **统一响应**：沿用 MineAdmin `Result` 结构；业务异常抛 `AppException(code, msg)`，全局异常处理器统一捕获，禁止堆栈外泄。
- **结构化日志**：PSR-3（Hyperf `Logger`），审批关键操作记录 `trace_id + user_id + instance_id + 耗时`，按 `oa/approval` 通道独立文件。
- **指标**：审批流转 P95 耗时、队列堆积长度、打卡接口错误率（中间件埋点，一期日志统计即可）。
- **告警**：日结任务失败、队列堆积超阈值 → 管理端站内信 + 邮件。

## 7. 部署拓扑（单机起步）

```
Nginx(HTTPS, 静态资源/反代)
  ├── /admin /h5  → Vue / uni-app-H5 构建产物（静态）
  └── /api        → MineAdmin(Hyperf, Swoole 多进程) ── MySQL 8.0
       /api       ← uni-app 小程序端直连（HTTPS 强制，微信平台硬性要求）
                                                └── Redis 6
                    └── Crontab 进程（考勤日结/公告定时）
Docker Compose 一键起：php+swoole / mysql / redis /（可选 libreoffice）
备份：mysqldump 每日全量 → 保留 7 天
```

**小程序发布链路**：微信后台配置合法域名 → 开发者工具上传 → 提交审核（企业主体）；
小程序登录所需 AppSecret / 订阅消息模板 ID 通过 `.env` 注入，**禁止明文写入代码与前端构建产物**。

环境要求：服务器 4C8G 起步；`.env` 管理 DB/Redis/JWT 密钥/微信凭据，**禁止明文入库**。
