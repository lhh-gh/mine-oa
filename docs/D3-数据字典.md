# MineAdmin OA 系统 — 数据字典（D3）

> 项目代号：MineOA
> 数据库：MySQL 8.0，引擎 InnoDB，字符集 utf8mb4，排序规则 utf8mb4_unicode_ci
> 命名规范：OA 业务表前缀 `oa_`；主键统一 `id BIGINT UNSIGNED AUTO_INCREMENT`；时间字段 `DATETIME`，默认 `CURRENT_TIMESTAMP`
> 版本：v0.1（初稿，待评审） ｜ 日期：2026-10-26

---

## 0. 模块与表总览

## 1. 审批中心【核心】

### 1.1 oa_approval_template — 审批模板

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK, AI | 模板 ID |
| name | VARCHAR(64) | NOT NULL | 模板名称，如"请假审批" |
| icon | VARCHAR(64) | NULL | 移动端入口图标标识 |
| node_schema | JSON | NOT NULL | 审批节点定义：`[{seq, name, approver_type, approver_ids[], is_parallel, reject_policy}]`，见下方说明 |
| cc_rule | JSON | NULL | 抄送人规则：固定人员 / 指定部门负责人 / 发起人自选 |
| reject_policy | TINYINT | NOT NULL DEFAULT 0 | 全局驳回策略：0=回退发起人 1=驳回终止 |
| status | TINYINT | NOT NULL DEFAULT 0 | 0=停用 1=启用 |
| remark | VARCHAR(255) | NULL | 备注 |
| created_by | BIGINT UNSIGNED | NOT NULL | 创建人 user_id |
| created_at / updated_at | DATETIME | 默认 CURRENT_TIMESTAMP / ON UPDATE | |

索引：`KEY idx_status (status)`

> **表单字段已行化**：模板的表单字段定义不再以 JSON 整体存储，拆分至 §1.1b
> `oa_approval_template_field`——字段定义需要参与查询、排序与逐字段校验，行化后可维护、可索引。
> `node_schema` 保留 JSON：属"整存整取"的结构定义（保存后整体读写、不参与查询），JSON 是合理边界。

> **node_schema 设计说明**：一期节点为顺序 + 并行会签两种，JSON 结构
> `{"nodes":[{"seq":1,"name":"直属主管审批","approver_type":"dept_leader|user|role","approver_ids":[1,2],"is_parallel":0,"pass_ratio":100},{"seq":2,"approver_type":"user","approver_ids":[3],"is_parallel":1,"pass_ratio":100}]}`
> `is_parallel=1` 且 `pass_ratio=100` 即会签（全部通过才前进）；`pass_ratio` 留扩展位，一期只支持 0/100。
> `approver_type=dept_leader` 时**复用 MineAdmin 内置 `dept_leader` 表**（部门 N:N 负责人）解析，
> 不自建负责人数据结构；解析兜底链见 D2 §4.1 B1。
> **模板只存"结构定义"，实例化后落入 1.3/1.4 表**，模板后续修改不影响进行中的审批。

> **月中查询的实时性保证**：日结表只含"已日结日期"。报表接口（D4

> "后半月数据为空"的假象。日结 Crontab 除每日 00:30 全量结算外，增加**每 2 小时增量结算**
> （仅处理当天有新打卡的用户），缩小实时计算窗口。

## 6. 设计决策要点

1. **模板/实例分离**：`node_schema`（定义）与 `oa_approval_node`（快照）分离，模板变更不影响在途审批——审批系统的关键不变式。
2. **两处乐观锁**：`instance.version`、`task.version` + Redis 锁 `mineoa:approval:task:{id}`，双保险防协程并发重复审批。
3. **JSON 字段使用边界（修订版）**：需参与查询的数据**一律行化**——表单字段定义已拆至 `oa_approval_template_field`；实例 `form_data` 中的 `searchable` 字段查询采用"MySQL 生成列 + 索引"（`JSON_EXTRACT` 提取 → 虚拟列 → 建索引），不做全表 JSON 扫描。仅"整存整取、不参与查询"的配置类数据保留 JSON（node_schema / cc_rule / perm / geo_fencing）。
4. **原始与日结分离**：打卡记录只追加、考勤日由 Crontab 日结生成（每日全量 + 每 2 小时增量），当月未结日期由报表 Service 实时计算合并，报表与打卡高峰互不干扰。
5. **只追加表**（approval_log / attendance_record / announcement_read）：审计与统计数据不允许 UPDATE，保证可回溯。
6. **复用优先**：审批人解析复用 MineAdmin `dept_leader` 表、员工身份复用 `user` 表（type 字段区分），不为 OA 自建平行组织/用户数据。
