# MineAdmin OA 系统 — 数据字典（D3）

> 项目代号：MineOA
> 数据库：MySQL 8.0，引擎 InnoDB，字符集 utf8mb4，排序规则 utf8mb4_unicode_ci
> 命名规范：OA 业务表前缀 `oa_`；主键统一 `id BIGINT UNSIGNED AUTO_INCREMENT`；时间字段 `DATETIME`，默认 `CURRENT_TIMESTAMP`
> 版本：v0.5（D9 整改：抄送/轮次快照、持久化消费收据、规则与部门历史、会话与私有文件）｜日期：2026-10-26
> 本文为待实现模型；所有新增表使用现有 databases/migrations 根目录迁移，种子位于 databases/seeders 根目录。

---

> 下文引用字段如 `user_id`、`dept_id`、`attachment_id` 均指向 MineAdmin 对应表。

## 1. 审批中心【核心】

### 1.1 oa_approval_template — 审批模板

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK, AI | 模板 ID |
| name | VARCHAR(64) | NOT NULL | 模板名称，如"请假审批" |
| icon | VARCHAR(64) | NULL | 移动端入口图标标识 |
| biz_type | VARCHAR(32) | NOT NULL DEFAULT 'common' | 关联业务单据类型：common/leave/expense/purchase/seal（leave 一阶段，其余三阶段） |
| form_schema | JSON | NOT NULL | 表单字段定义（**版本化整体存储**）：`[{fieldKey,label,type,required,options,sort}]`，type ∈ text/number/amount/date/daterange/image/attachment；**固定查询字段不在此**，落业务单据表列（见 §2） |
| node_schema | JSON | NOT NULL | 审批节点定义：`{"nodes":[{"seq":1,"name":"直属主管审批","approver_type":"dept_leader","approver_ids":[],"reject_policy":0}]}`；一阶段仅顺序节点（三阶段会签扩展 is_parallel，仅全员通过，不设计 pass_ratio） |
| allowed_scope | JSON | NOT NULL | 发起范围：`{"mode":"departments","dept_ids":[1]}`，服务端按生效办公主部门校验；默认仅显式授权部门 |
| fallback_approver | JSON | NULL | B1 业务兜底审批人：`{"type":"user","ids":[1]}`（非超管；解析链 ①dept_leader ②上溯父部门 ③兜底 ④仍无则阻止提交） |
| cc_rule | JSON | NULL | 抄送人规则：固定人员 / 指定部门负责人 / 发起人自选 |
| reject_policy | TINYINT | NOT NULL DEFAULT 0 | 全局驳回策略：0=回退发起人 1=驳回终止 |
| remind_days / escalate_days | INT | NOT NULL DEFAULT 7 / 30 | 活动节点提醒/升级门槛，正数且升级大于提醒 |
| version | INT | NOT NULL DEFAULT 1 | **模板版本号**：每次修改 +1，用于审计与在途实例隔离判断 |
| status | TINYINT | NOT NULL DEFAULT 0 | 0=停用 1=启用 |
| remark | VARCHAR(255) | NULL | 备注 |
| created_by | BIGINT UNSIGNED | NOT NULL | 创建人 user_id |
| created_at / updated_at | DATETIME | 默认 CURRENT_TIMESTAMP / ON UPDATE | |

索引：`KEY idx_status (status)`

> **JSON 边界（修订，对应 D5 P1-2）**：表单字段定义与节点结构属"整存整取的结构定义"，
> 回归版本化 JSON 存储（v0.1 的"字段一律行化"修正过度，已撤回）；
> **需要参与查询/校验的固定字段（假别、起止时间、金额等）落在业务单据表的实列上并建索引**。
> approver_type枚举为dept_leader/user/role，approver_ids在user类型为员工ID、role类型为角色ID、dept_leader类型为空；一阶段解析结果必须恰好一人，多人时要求管理员改为显式单人节点。allowed_scope.mode为all_employee/departments，后者dept_ids非空。
> `approver_type=dept_leader` 时复用 MineAdmin 内置 `dept_leader` 关联（部门 N:N 负责人）解析；
> 模板只存"结构定义"，实例化后落入 1.3/1.4 表并冻结表单定义（见 1.2），模板后续修改不影响在途审批。

## 2. 业务单据【核心，对应 D5 P1-2】

> 通用审批实例承载流转与留痕；结构化业务数据落各自单据表（固定列、可索引、可校验），
> 与实例 1:1。`form_data` 仅承载附加说明字段。

## 3. 考勤【核心，二阶段】

### 3.1 oa_attendance_rule — 不可变考勤规则版本（二阶段）

| 字段 | 类型 | 约束/说明 |
| --- | --- | --- |
| id | BIGINT UNSIGNED | PK, AI，规则版本ID |
| rule_key / version | VARCHAR(64) / INT | NOT NULL，UNIQUE(rule_key,version) |
| name | VARCHAR(64) | NOT NULL |
| work_start / work_end | TIME | 固定白班，必须 work_start<work_end |
| lunch_start / lunch_end | TIME | NULL或完整成对，位于工作时段内 |
| late_threshold / early_threshold | INT | NOT NULL DEFAULT 0，非负分钟 |
| punch_open / punch_close | TIME | NOT NULL，允许打卡的当日窗口，默认06:00:00至23:59:59，不跨日 |
| workdays / holidays | JSON | 周工作日与日期例外，整存整取 |
| ip_ranges | JSON | 允许IP网段；客户端IP取受信任反代链 |

不在 JSON 列上建立字符串前缀索引。规则停用通过结束适用区间实现，不删除历史版本。

### 3.1.1 oa_attendance_rule_department — 部门适用区间（二阶段）

| 字段 | 类型/约束 | 说明 |
| --- | --- | --- |
| id | BIGINT UNSIGNED PK, AI | |
| rule_id | BIGINT UNSIGNED NOT NULL | 引用不可变规则版本 |
| dept_id | BIGINT UNSIGNED NOT NULL | 0为默认规则；非0引用department |
| effective_from / effective_to | DATE / DATE NULL | 左闭右开区间；NULL表示无结束日期 |
| created_by / created_at | BIGINT UNSIGNED / DATETIME | |

索引 UNIQUE(dept_id,effective_from)、idx_dept_period(dept_id,effective_from,effective_to)。

## 7. 实施约束

1. 时间使用Asia/Shanghai；区间采用左闭右开，起止必须合法；JSON结构在Request边界校验。
2. 新增OA接口的主键BIGINT对外按字符串传输，避免JS整数精度丢失；DTO字段映射由D4规定。
3. 模板结构、每轮输入快照、节点和任务轮次共同保证历史还原；当前单据不用于反推旧轮次。
4. 数据权限表列和onlyTables见D2，个人归属与部门授权分别校验；空范围默认无数据。
5. Outbox生产、内部副作用和收据的事务边界见D2；外部服务不承诺数据库式原子提交。
6. rule/day/主部门历史纠错必须记录旧值、新值、操作者与原因；普通重算不改历史归属。
7. 文档、单据和导出附件为私有；审批日志/原始打卡/轮次内容仅追加，保留策略在上线前确认。
8. 数据字典新增表及约束均待迁移实现，不能因本文件修订而标为已建表或已验收。
