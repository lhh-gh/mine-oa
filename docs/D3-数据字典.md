# MineAdmin OA 系统 — 数据字典（D3）

> 项目代号：MineOA
> 数据库：MySQL 8.0，引擎 InnoDB，字符集 utf8mb4，排序规则 utf8mb4_unicode_ci
> 命名规范：OA 业务表前缀 `oa_`；主键统一 `id BIGINT UNSIGNED AUTO_INCREMENT`；时间字段 `DATETIME`，默认 `CURRENT_TIMESTAMP`
> 版本：v0.2（修订稿，已合入 D5 两轮复审意见：模板字段定义版本化 JSON、业务单据表、Outbox 事件表、审批轮次、考勤规则生效日期、`user_type` 修正）｜日期：2026-10-26

---

## 0. 模块与表总览

| 模块 | 表 | 阶段 |
| --- | --- | --- |
| 审批中心 | oa_approval_template / oa_approval_instance / oa_approval_node / oa_approval_task / oa_approval_log | 一阶段 |
| 业务单据 | **oa_leave_bill（请假）** / oa_expense_bill（报销） / oa_purchase_bill（采购） / oa_seal_bill（用章） | 请假一阶段；其余三阶段 |
| 考勤 | oa_attendance_rule / oa_attendance_record / oa_attendance_day / oa_attendance_correct（补卡） | 二阶段 |
| 公告 | oa_announcement / oa_announcement_read | 三阶段 |
| 文档中心 | oa_doc_folder / oa_doc_file | 三阶段 |
| 消息中心 | oa_message / oa_message_push（订阅消息推送记录） | 一阶段（消息）/ 三阶段（推送） |
| 可靠投递 | **oa_event_outbox（Outbox 事件表）** | 一阶段 |
| 移动端 | oa_wechat_binding（小程序账号绑定） | 一阶段 |

> MineAdmin 内置表（user / role / menu / department / dept_leader / attachment 等）不在本字典中重复设计，直接复用其结构。
> ⚠️ 用户类别字段为 **`user_type`**（v3 官方数据模型契约，枚举如 `Type::SYSTEM`），非 `type`；具体取值以锁定版本迁移文件为准（D5 P2-1 / 第二轮 N2）。
> 下文引用字段如 `user_id`、`dept_id`、`attachment_id` 均指向 MineAdmin 对应表。

## 1. 审批中心【核心】

### 1.1 oa_approval_template — 审批模板

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK, AI | 模板 ID |
| name | VARCHAR(64) | NOT NULL | 模板名称，如"请假审批" |
| icon | VARCHAR(64) | NULL | 移动端入口图标标识 |
| biz_type | VARCHAR(32) | NOT NULL DEFAULT 'common' | 关联业务单据类型：common/leave/expense/purchase/seal（leave 一阶段，其余三阶段） |
| form_schema | JSON | NOT NULL | 表单字段定义（**版本化整体存储**）：`[{fieldKey,label,type,required,options,sort}]`，type ∈ text/number/amount/date/daterange/image/attachment；**固定查询字段不在此**，落业务单据表列（见 §2） |
| node_schema | JSON | NOT NULL | 审批节点定义：`{"nodes":[{"seq":1,"name":"直属主管审批","approver_type":"dept_leader\\|user\\|role","approver_ids":[1,2],"reject_policy":0}]}`；一期仅顺序节点（会签三阶段扩展 `is_parallel`/`pass_ratio`） |
| fallback_approver | JSON | NULL | B1 业务兜底审批人：`{"type":"user\\|role","ids":[..]}`（非超管；解析链 ①dept_leader ②上溯父部门 ③兜底 ④仍无则阻止提交） |
| cc_rule | JSON | NULL | 抄送人规则：固定人员 / 指定部门负责人 / 发起人自选 |
| reject_policy | TINYINT | NOT NULL DEFAULT 0 | 全局驳回策略：0=回退发起人 1=驳回终止 |
| version | INT | NOT NULL DEFAULT 1 | **模板版本号**：每次修改 +1，用于审计与在途实例隔离判断 |
| status | TINYINT | NOT NULL DEFAULT 0 | 0=停用 1=启用 |
| remark | VARCHAR(255) | NULL | 备注 |
| created_by | BIGINT UNSIGNED | NOT NULL | 创建人 user_id |
| created_at / updated_at | DATETIME | 默认 CURRENT_TIMESTAMP / ON UPDATE | |

索引：`KEY idx_status (status)`

> **JSON 边界（修订，对应 D5 P1-2）**：表单字段定义与节点结构属"整存整取的结构定义"，
> 回归版本化 JSON 存储（v0.1 的"字段一律行化"修正过度，已撤回）；
> **需要参与查询/校验的固定字段（假别、起止时间、金额等）落在业务单据表的实列上并建索引**。
> `approver_type=dept_leader` 时复用 MineAdmin 内置 `dept_leader` 关联（部门 N:N 负责人）解析；
> 模板只存"结构定义"，实例化后落入 1.3/1.4 表并冻结表单定义（见 1.2），模板后续修改不影响在途审批。

## 3. 考勤【核心，二阶段】

### 3.1 oa_attendance_rule — 考勤规则

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PK, AI | |
| name | VARCHAR(64) | NOT NULL | 规则名称，如"行政班 9-18" |
| work_start / work_end | TIME | NOT NULL | 上/下班时间（**一期固定白班单段**） |
| lunch_start / lunch_end | TIME | NULL | 午休时段（时长计算扣除；NULL=不扣） |
| late_threshold / early_threshold | INT | NOT NULL DEFAULT 0 | 迟到/早退阈值（分钟） |
| workdays | JSON | NOT NULL | 工作日：`[1,2,3,4,5]`（周一=1，周日=7） |
| holidays | JSON | NULL | 法定节假日例外：`{"2026-10-01":"holiday","2026-10-08":"workday"}` |
| **effective_date** | DATE | NOT NULL DEFAULT '1970-01-01' | **规则生效日期**（新规则只影响之后日期，历史结算不回算） |
| ip_ranges | JSON | NULL | 允许打卡的 IP 段（一期方案；地理位置围栏默认不启用，隐私合规） |

| status | TINYINT | NOT NULL DEFAULT 1 | 0=停用 1=启用 |

索引：`KEY idx_effective (dept_scope(64), effective_date)`（取适用规则时按生效日期选最新）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |

| user_id | BIGINT UNSIGNED | NOT NULL | |

| type | TINYINT | NOT NULL | 1=上班卡 2=下班卡 |

### 3.3 oa_attendance_day — 考勤日结表（日终生成 + 可重算，报表只查此表）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |

| status | TINYINT | NOT NULL | 0=休息日 1=正常 2=迟到 3=早退 4=迟到且早退 5=缺卡 6=旷工 7=请假 8=外勤（扩展位） |

## 7. 设计决策要点（修订）

1. **模板/实例分离 + 双重冻结**：`form_snapshot`（表单定义快照）+ 节点快照 + `template_version`，模板变更不影响在途/历史审批，审批历史可完整还原（D5 P0-5）。
2. **三层并发防护**：实例级分布式锁（固定顺序 instance→node→task）+ `instance.version`/`task.version` 乐观锁 + 事务内二次校验（D5 P0-3）。
3. **JSON 使用边界（二次修订）**：结构定义（form_schema / node_schema / cc_rule / perm）版本化 JSON 整存整取；**固定查询/校验字段一律落业务单据表实列**（请假起止时间、报销金额等），v0.1 的"字段定义行化"已撤回（过度设计）、v0.1 的"form_data 生成列索引"随之不再需要（D5 P1-2）。
4. **Outbox 可靠投递**：跨模块副作用（考勤联动、消息推送、重算）一律经 `oa_event_outbox` 同事务落库、异步投递、按事件 ID 幂等消费（D5 P0-4）。
5. **原始与日结分离 + 可重算**：打卡记录只追加、同步落库；考勤日由 Crontab 日结生成且幂等可重算，`effective_date` 隔离历史（D5 P0-2 / P1-3）。
6. **只追加表**（approval_log / attendance_record / announcement_read）：审计与统计数据不允许 UPDATE，保证可回溯；任务表"作废"仅限未处理任务。
7. **复用优先**：审批人解析复用 MineAdmin `dept_leader` 关联、员工身份复用 `user` 表（**`user_type`** 字段区分类别）、附件复用 `attachment`，不为 OA 自建平行组织/用户数据。
