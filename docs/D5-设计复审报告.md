# MineAdmin OA 系统 — 设计复审报告

> 评审对象：D1《用户需求梳理》/ D2《项目技术架构》/ D3《数据字典》/ D4《API 接口文档》
> 评审轮次：第一轮（2026-10-26，v0.1 初稿）＋ 第二轮（2026-10-26，对照 MineAdmin 官方文档核实）＋ 第三轮（2026-10-26，用户确认 MineAdmin 3.2 与 unibest 选型）＋ 第四轮（2026-10-26，用户决策变更：OA 不采用插件化，见 §3.4）

## 1. 总体结论

1. **MineAdmin 3.x 选型成立**：内置 RBAC / 部门 / `dept_leader` 负责人 / 附件 / 操作日志与 OA 高度重合；
   基于 Hyperf，协程、队列、Crontab 齐备；官方提供插件体系与多场景 JWT 方案（均已核实存在）。
2. **架构方向成立**：单体模块化（<500 人，OA 代码直接置于主工程 App 层，不采用插件体系，见 §3.4）、
   自研有限审批状态机、uni-app 双端，
   核心决策均无推翻必要。
3. **两轮复审累计发现 19 项问题**（第一轮 P0×5 / P1×5 / P2×2，第二轮 N×7），
   主要集中在三类：对 MineAdmin 3.x 实际形态的认知偏差、数据可信/一致性、业务建模完整性。
   已全部落入 D1–D4 v0.2。
4. **编码前唯一硬性前置**：锁定 MineAdmin 具体版本并以其源码核对事实性引用（§5 遗留事项）。
