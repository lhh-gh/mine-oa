## 1. 测试策略分层

| 层 | 工具 | 范围 | 覆盖率要求 |
| --- | --- | --- | --- |
| 单元测试 | PHPUnit 10 + Hyperf 协程测试 | 状态机、审批人解析器、请假时长计算（午休扣除）、重叠校验、转交链检测 | 状态机与解析器**分支覆盖 100%** |
| 集成测试 | PHPUnit + 内存 SQLite/容器 MySQL | Service 事务边界（实例/节点/任务/日志/Outbox 同事务）、日结重算、补卡修正 | 核心路径 100%，异常路径至少各 1 例 |
| 接口测试 | Hyperf HTTP 测试客户端 | 全部 `/admin/oa/*`、`/api/oa/*` 契约与错误码（对齐 D4） | 每接口正常 + 主要错误码 |
| 专项并发测试 | 多协程/多进程脚本 | 同一待办双人处理、处理与撤回并发、会签并发（三阶段） | 结论唯一：副作用仅发生一次 |
| 数据权限专项 | 接口测试 | DEPT_TREE/SELF 策略 + OA 表列映射 | 越权访问被拦截（D1 验收 5） |

> Hyperf 协程环境运行 PHPUnit 需在测试基类中显式 `co-run` 包裹（官方 `Hyperf\Testing` 支持）；
> 数据库用事务回滚或逐用例重建种子数据，保证用例幂等可重复执行。

## 2. 用例矩阵（编号规范 T-{模块}-{序号}，映射复审问题）

### 2.1 状态机（T-SM）

| 用例 | 前置 | 操作 | 断言 |
| --- | --- | --- | --- |
| T-SM-01 | DRAFT | SUBMIT | → PENDING；产生首节点任务与 log(action=1) |
| T-SM-02 | DRAFT | CANCEL | → CANCELED（终态） |
| T-SM-03 | PENDING 末节点 | 全员 APPROVE | → APPROVED；写 log(2) + Outbox(approval.finished) |
| T-SM-04 | PENDING | REJECT_TO_START（模板策略 0） | → DRAFT；round+1；未处理任务作废(log 7)，已处理任务/日志全保留 |
| T-SM-05 | PENDING | REJECT_END（模板策略 1） | → REJECTED（终态） |
| T-SM-06 | PENDING 首节点未处理 | CANCEL | → CANCELED；首节点未处理任务作废 |
| T-SM-07 | PENDING 首节点已处理 | CANCEL | 拒绝：非法状态转移（110004） |
| T-SM-08 | 任一状态 | 未定义事件 | 抛 DomainException → 110004，无任何写库副作用 |

### 2.3 打卡与考勤（T-AT）

### 2.4 并发与一致性（T-CC，对应 P0-3/P0-4）

| 用例 | 场景 | 操作 | 断言 |
| --- | --- | --- | --- |
| T-CC-01 | 同一待办，两协程同时 act | 并发调用 | **仅一协程成功**，另一协程 110002；任务/日志/实例 version 只前进一次 |
| T-CC-02 | 一人 act 同意 与 发起人 cancel 并发 | 并发调用 | 恰好一个成功（实例级锁序 instance→node→task）；状态机无非法终态 |
| T-CC-03 | 事务提交后进程"崩溃"（模拟：提交后抛出） | 触发审批通过 | Outbox 表已有事件行（同事务）；投递任务重启后补投，考勤联动最终发生 |

## 3. 示例测试骨架

```php
<?php
// tests/OA/TestCase.php —— 协程测试基类
// 依赖：hyperf/testing；所有 Service 级用例在协程内执行，避免连接池跨协程误用
// autoload-dev：composer.json 注册 "Tests\\": "tests/"（编码首日以 3.2 项目实际 autoload-dev 为准）
namespace Tests\OA;

use Hyperf\Testing\TestCase as BaseTestCase;

abstract class TestCase extends BaseTestCase
{
    /** 在协程内执行用例主体，结束后清理该协程持有的连接 */
    protected function runInCoroutine(callable $fn): mixed
    {
        $result = null;
        \Swoole\Coroutine\run(function () use ($fn, &$result) {
            try {
                $result = $fn();
            } finally {
                // 归还连接，防止用例间连接池污染（对应 D2 §6.3 工程约束）
                \Hyperf\Utils\ApplicationContext::hasContainer()
                    && \Hyperf\Database\Connectors\ConnectionFactory::class;
            }
        });
        return $result;
    }
}
```

```php
<?php
// tests/OA/Unit/StateMachine/TransitionTest.php
// 状态机全路径覆盖：合法转移 + 非法转移
namespace Tests\OA\Unit\StateMachine;

use PHPUnit\Framework\Attributes\DataProvider;
use App\Service\OA\StateMachine\ProcessStatus;
use App\Service\OA\StateMachine\Transition;

final class TransitionTest extends \PHPUnit\Framework\TestCase
{
    public static function legalProvider(): array
    {
        return [
            'DRAFT+SUBMIT' => [ProcessStatus::DRAFT, 'SUBMIT', ProcessStatus::PENDING],
            'PENDING+APPROVE_ALL' => [ProcessStatus::PENDING, 'APPROVE_ALL', ProcessStatus::APPROVED],
            'PENDING+REJECT_TO_START' => [ProcessStatus::PENDING, 'REJECT_TO_START', ProcessStatus::DRAFT],
            'PENDING+REJECT_END' => [ProcessStatus::PENDING, 'REJECT_END', ProcessStatus::REJECTED],
            'PENDING+CANCEL' => [ProcessStatus::PENDING, 'CANCEL', ProcessStatus::CANCELED],
        ];
    }

    #[DataProvider('legalProvider')]
    public function testLegalTransition(ProcessStatus $from, string $event, ProcessStatus $to): void
    {
        $this->assertSame($to, Transition::go($from, $event));
    }

    /** 所有未定义组合必须抛异常（安全边界：不可被绕过） */
    public function testIllegalTransitionThrows(): void
    {
        $this->expectException(\DomainException::class);
        Transition::go(ProcessStatus::APPROVED, 'SUBMIT'); // 终态不可再转移
    }
}
```

```php
<?php
// tests/OA/Concurrent/ActConcurrencyTest.php
// T-CC-01：同一待办双人（双协程）同时处理，仅一人成功
namespace Tests\OA\Concurrent;

final class ActConcurrencyTest extends \Tests\OA\TestCase
{
    public function testOnlyOneCoroutineWins(): void
    {
        [$instanceId, $taskId, [$approverA, $approverB]] = $this->seedPendingApproval();

        $results = [];
        \Swoole\Coroutine\run(function () use (&$results, $taskId, $approverA, $approverB) {
            $wg = new \Swoole\Coroutine\WaitGroup();
            // 两个协程以各自用户身份同时 act（模拟真实并发，无人工 sleep 排序）
            foreach ([[$approverA], [$approverB]] as $pair) {
                $wg->add();
                \Swoole\Coroutine\create(function () use ($wg, &$results, $taskId, $pair) {
                    try {
                        $results[] = $this->approvalService->act($pair[0], $taskId, 1, '同意');
                    } catch (\App\Exception\OA\AppException $e) {
                        $results[] = $e->getCode(); // 期望捕获 110002
                    } finally {
                        $wg->done();
                    }
                });
            }
            $wg->wait();
        });

        $okCount = count(array_filter($results, fn ($r) => $r instanceof ActResult));
        $this->assertSame(1, $okCount, '同一待办必须恰好被处理一次');
        $this->assertContains(110002, $results, '失败方必须返回任务已被处理');
    }
}
```

## 4. 验证脚本（命令行冒烟清单）

发布前/上线后执行 `php bin/hyperf.php oa:smoke`（自定义 Command，只读为主，失败非零退出）：

| 步骤 | 检查项 | 通过标准 |
| --- | --- | --- |
| 1 | DB/Redis 连接与连接池 | 连接可用，池参数符合 D2 §6.3 |
| 2 | 状态机自检 | Transition 全转移表自测通过 |
| 3 | Outbox 健康 | status=0 且 next_retry_at<now 的积压 ≤ 阈值；无死信堆积 |
| 4 | Crontab 注册 | 日结/超时提醒/定时发布任务注册成功 |
| 5 | 数据权限探针 | 以测试账号请求月报接口，返回行数符合策略 |
| 6 | 短信/微信凭据 | `.env` 凭据存在（不回显值），模板/签名配置完整 |

> CI 建议：GitHub Actions/GitLab CI 内 `docker compose up mysql redis` + 容器化 PHP(8.2/Swoole)
> 跑全量测试；并发用例（T-CC-01/02）必须在 CI 中稳定可重复（禁 sleep 排序）。
