> 项目代号：MineOA
> 版本：v0.2（基线：MineAdmin 3.2 已锁定；移动端 unibest 构建命令）｜日期：2026-10-26
> 覆盖目标：D5 遗留 L4 —— Swoole 常驻内存的发布/重启流程、内存监控展开

## 1. 环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 服务器 | 4C8G 起步，系统盘 ≥ 40GB（日志+备份） | 单机起步；HTTPS 证书必备（小程序硬性要求） |
| PHP | 8.2+，Swoole 5.1+（禁 Short Name） | 扩展：mbstring/json/pdo/openssl/redis/pcntl |
| MySQL | 8.0，InnoDB，utf8mb4 | `innodb_buffer_pool_size` 建议 2G+ |
| Redis | 6.0+ | 缓存 + 队列 + 锁 |
| Node.js | 20+，pnpm ≥ 9（仅构建期） | 构建 MineAdmin 后台前端（含 OA 页面）与 unibest（H5/小程序）产物 |
| 可选组件 | LibreOffice headless（Docker，三阶段） | Office 转 PDF 预览 |
| 外部服务 | 阿里云短信（AccessKey）、微信小程序（AppID/AppSecret/订阅模板） | 凭据见 §2，签名/模板需提前报备（1~2 工作日） |

## 2. 配置清单（.env，禁止明文入库/入仓）

```ini
# 数据库 / 缓存
DB_HOST=127.0.0.1  DB_PORT=3306  DB_DATABASE=mineoa  DB_USERNAME=***  DB_PASSWORD=***
REDIS_HOST=127.0.0.1  REDIS_PORT=6379

# JWT 双场景（官方多场景方案，密钥相互隔离；openssl rand -base64 64 生成）
JWT_SECRET=<后台密钥>
JWT_MOBILE_SECRET=<移动端密钥>

# 微信小程序
WX_MINI_APPID=wx***  WX_MINI_SECRET=***          # 只存服务端
WX_SUBSCRIBE_TEMPLATE_APPROVAL_TODO=***           # 订阅消息模板 ID

# 短信（阿里云）
SMS_ACCESS_KEY_ID=***  SMS_ACCESS_KEY_SECRET=***
SMS_SIGN_NAME=企业签名  SMS_TEMPLATE_LOGIN=SMS_***

# MineAdmin 插件市场（如需拉取官方插件）
MINE_ACCESS_TOKEN=***
```

> 安全基线：`.env` 不进 Git（`.gitignore`）；生产与测试密钥必须不同；
> JWT 密钥 ≥ 256 位随机串（官方要求）。

## 3. 部署拓扑与 Docker Compose

```
Nginx(443, HTTPS)
  ├── /admin        → MineAdmin 后台前端构建产物（OA 页面在主前端工程内一并构建，静态）
  ├── /h5           → uni-app H5 构建产物（静态）
  ├── /api          → php-swoole 容器:9501（反代）
  └── 小程序端      → 直连 https://域名/api（合法域名后台配置）

php-swoole ── MySQL8.0 ── Redis6
   └── Crontab 进程（考勤日结 00:30 / Outbox 投递 / 节点超时提醒 / 公告定时发布）
（三阶段追加：libreoffice 容器，仅内网可达）
```

**docker-compose.yml 服务清单**（示意）：

| 服务 | 镜像/构建 | 端口 | 备注 |
| --- | --- | --- | --- |
| php-swoole | 自建（php:8.2-cli + swoole 扩展 + composer install） | 9501（仅内网） | 常驻进程，见 §4 发布流程 |
| mysql | mysql:8.0 | 3306（仅内网） | 数据卷持久化；每日备份见 §6 |
| redis | redis:6 | 6379（仅内网） | appendonly 开启 |
| nginx | nginx:stable | 443 | HTTPS 证书挂载；静态产物只读挂载 |

**首次部署步骤**：

1. 服务器拉取项目，配置 `.env`（§2）。
2. `docker compose up -d mysql redis`，建库（utf8mb4）。
3. `php bin/hyperf.php mine:install`（MineAdmin 安装，主干迁移 + 种子）→ `php bin/hyperf.php migrate` 执行 `oa_*` 迁移 → `seeders/oa/` 权限点/菜单 Seeder 写入（OA 为主工程 App 层模块，非插件，无插件安装环节）。
4. 构建：后台前端 `pnpm build`（OA 页面在 `web/src/views/oa/`，随主前端一并构建；首次先验证一个 OA 页面可挂菜单）→ 部署到 Nginx `/admin`；unibest：`pnpm build:h5`（产物部署到 Nginx `/h5`）与 `pnpm build:mp-weixin`（微信开发者工具上传审核）。
5. `docker compose up -d php-swoole nginx`；执行 `php bin/hyperf.php oa:smoke`（D6 §4 冒烟清单）。
6. 微信后台配置 request 合法域名（`https://域名/api`），上传体验版走通 T-SEC-05/订阅消息链路。

## 4. 发布与重启流程（Swoole 常驻内存，关键）

> 常驻内存**无 PHP-FPM 式"传完即生效"**，任何后端代码/配置变更必须重启进程（D2 §6.3）。

**标准发布步骤**：

```bash
# 1. 拉取代码 + composer install（生产不装 dev 依赖）
git pull && composer install --no-dev --optimize-autoloader

# 2. 重启 Hyperf 进程（平滑 reload；pid 文件位于 runtime/hyperf.pid）
kill -USR1 $(cat runtime/hyperf.pid)        # reload Worker，重建连接池
# 或容器化环境：
docker compose restart php-swoole

# 3. 健康检查（失败立即回滚）
php bin/hyperf.php oa:smoke && curl -fsS https://<域名>/health || docker compose rollback
```

- **停机窗口**：reload 期间在途请求会等待完成（秒级），选择非工作时段（22:00 后）发布；
  打卡高峰（08:30–09:00）与日结窗口（00:30）禁止发布。
- **数据库变更**：迁移在 reload 前执行，遵循"只增不破坏"（新增列可空/有默认值），
  保证新旧代码短暂共存期不出错。
- **回滚**：`git revert` 到上一 tag → 重新 composer install → 重启；迁移原则上不回滚，
  靠"只增不破坏"保证兼容。

## 5. 定时任务与后台进程

| 任务 | 计划 | 说明 |
| --- | --- | --- |
| 考勤日结 | 每日 00:30 全量 + 当日有新打卡用户的增量重算 | 幂等 UPSERT（D3 §3.3）；失败告警 |
| Outbox 投递 | 常驻（秒级扫描 `status=0 AND next_retry_at<=now`） | 失败退避 1/5/30min，3 次转死信；**积压/死信超阈值告警** |
| 节点超时提醒 | 每日扫描 ACTIVE 超 7/30 天节点 | 分级提醒（D2 §4.1 B2） |
| 公告定时发布 | 每分钟扫描 | 三阶段 |
| 备份 | 每日 01:30（见 §6） | |

> 全部任务随 Hyperf 进程内 Crontab 运行，随发布自动重启；无需额外 crontab 条目。

## 6. 备份与恢复

```bash
# 每日全量（Crontab 调用），保留 7 天
mysqldump --single-transaction --routines --triggers -u*** -p*** mineoa \
  | gzip > /backup/mineoa-$(date +%F).sql.gz
```

- 备份目录**每日校验存在与体积**（<80% 昨日体积视为异常告警）。
- **恢复演练每季度一次**：`gunzip < dump | mysql mineoa` → `oa:smoke` 全绿 → 恢复结果记录归档。
- Redis 数据可丢（缓存/锁/计数器可重建）；重要业务状态以 MySQL 为唯一事实源（Outbox 已保证）。

## 7. 监控与告警

| 指标 | 采集 | 告警阈值 | 通道 |
| --- | --- | --- | --- |
| 接口 P95 耗时（审批/打卡） | 中间件埋点日志聚合 | > 500ms 持续 5min | 站内信 + 邮件 |
| 错误率 | 全局异常处理器计数 | > 1% 持续 5min | 同上 |
| Outbox 积压/死信 | 投递任务自检 | 积压 > 100 或死信 > 0 | 同上 |
| 队列堆积 | 队列长度 | > 1000 | 同上 |
| Worker 内存 | `memory_get_usage` 周期上报（D2 §6.3） | > 80% `memory_limit` | 同上 |
| 进程存活 | 健康检查 `/health`（外部拨测） | 连续 3 次失败 | 短信（关键） |
| 日结任务 | 任务结果日志 | 失败即告警 | 站内信 + 邮件 |

日志规范：PSR-3 结构化（`trace_id/user_id/instance_id/耗时`），`oa/approval` 通道独立文件，
按天轮转保留 30 天。

## 8. 小程序发布链路

1. 微信公众平台：配置服务器合法域名（request：`https://<域名>`，必须是 HTTPS + 备案域名）。
2. uni-app 构建微信小程序包 → 开发者工具上传 → 提交审核（企业主体，类目"办公"）。
3. 订阅消息模板在平台申请（`approval_todo`），模板 ID 配置到 `.env`。
4. AppSecret **只存服务端**；`session_key` 不下发（D6 T-SEC-05 验证）。

## 9. 常见故障排查

| 现象 | 排查顺序 |
| --- | --- |
| 早高峰打卡慢 | ① 慢查询日志（uk 冲突重试）② 连接池耗尽（pool 配置 ≤ 64/Worker）③ P95 日志定位是否锁等待 |
| Outbox 积压增长 | ① 投递任务日志（微信/短信上游错误码）② `next_retry_at` 分布 ③ 死信表人工处理后重投 |
| 内存持续上涨 | ① Worker 内存曲线（§7）② 排查静态属性持有大对象（D2 §6.3）③ 定时 reload 兜底并立项修复 |
| 员工收不到待办提醒 | ① `oa_message` 是否落库（站内保底必然可达）② `oa_message_push` err_code（订阅授权消费完 → 引导重新授权）③ 用户是否授权 |
| 修改代码不生效 | 常驻内存：确认执行了 §4 重启流程（含 reload 后 `oa:smoke`） |
| 审批待办卡死 | ① 实例节点状态（B2 超时任务是否运行）② `dept_leader` 是否被清空（B1 解析链日志）③ 分布式锁残留（TTL 应自动过期） |
