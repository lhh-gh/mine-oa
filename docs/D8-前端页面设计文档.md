# MineAdmin OA 系统 — 前端页面设计文档（D8）

> 项目代号：MineOA
> 范围：web 后台前端（`MineAdmin/web`，Vue3 + Element Plus）+ mobile 移动端（`MineAdmin/mobile`，unibest v4.4.1）
> 依据：D1 需求分期、D4 接口契约（路由 `/admin/oa/*` 与 `/api/v1/oa/*`）、D3 数据字典、D2 架构
> 版本：v0.1｜日期：2026-10-26

---

## 1. web 后台前端（OA 页面）

### 1.1 模块结构（对齐 MineAdmin 官方 base 模块约定）

```
web/src/modules/oa/
├── api/                          # 接口封装，按域拆分（对应 D4 管理端接口）
│   ├── approval.ts               # 模板 CRUD、审批发起/待办/处理/撤回（后台流程入口）
│   ├── attendance.ts             # 规则、报表、补卡（二阶段）
│   ├── announcement.ts           # 公告管理（三阶段）
│   └── document.ts               # 文档管理（三阶段）
├── views/
│   ├── approval/
│   │   ├── template/             # 模板管理
│   │   │   ├── index.vue         # 列表（ma-table，搜索：name/status/bizType）
│   │   │   ├── form.vue          # 模板编辑（抽屉/弹窗）
│   │   │   └── data/
│   │   │       ├── getTableColumns.tsx
│   │   │       └── getSearchItems.tsx
│   │   ├── process/              # 后台完整审批入口（D4 补齐项）
│   │   │   ├── mine.vue          # 我的申请
│   │   │   ├── todo.vue          # 待我审批（角标）
│   │   │   └── done.vue          # 我已审批
│   │   └── detail/index.vue      # 审批详情（动态表单 + 轮次时间线 + 业务单据卡片）
│   ├── attendance/               # 二阶段
│   │   ├── rule/index.vue        # 考勤规则管理
│   │   ├── report/index.vue      # 部门月报（DataScope 过滤）
│   │   └── correct/index.vue     # 补卡记录
│   ├── announcement/             # 三阶段：公告管理（富文本 + 定时发布 + 已读统计）
│   └── document/                 # 三阶段：文档中心（目录树 + 文件列表 + 权限配置）
├── components/                   # OA 专用通用组件
│   ├── DynamicForm/index.vue     # ★ 按 formSchema（D3 §1.1）动态渲染 + 校验（双端共用逻辑）
│   ├── NodeSchemaEditor/index.vue# ★ 节点配置器（seq 连续校验、approver_type 切换、兜底审批人）
│   ├── ApprovalTimeline/index.vue# 审批时间线（含 round 轮次、action 语义、system auto-pass）
│   └── BizDataCard/index.vue     # 业务单据卡片（请假/报销/采购/用章 按 bizType 分发）
└── locales/zh_CN[简体中文].yaml
```

> 约定沿用 base 模块：列表页 `index.vue` + `data/getTableColumns.tsx` + `getSearchItems.tsx` +
> `form.vue`；接口走 `useHttp`；表格走 `useTable`；权限用 `v-auth` 指令与 `hasAuth()`。
> 页面接入后台「菜单管理」，组件路径指向 `modules/oa/views/...`（首个页面先验证可挂菜单）。

### 1.2 页面清单与权限点映射

| 页面 | 阶段 | 核心交互 | 对应接口（D4） | 权限点 |
| --- | --- | --- | --- | --- |
| 审批模板列表/编辑 | 一 | formSchema 字段设计器（拖拽/JSON 双模式）+ NodeSchemaEditor + 兜底审批人；保存 version+1 | template/list、save、change-status | oa:approval:template:* |
| 我的申请/待办/已办 | 一 | 后台完整审批入口（与移动端同 Service）：发起（DynamicForm）、act、cancel、resubmit | 后台流程接口（admin/oa/approval/*，D4 待补全） | oa:approval:process:* |
| 审批详情 | 一 | BizDataCard + DynamicForm 只读 + ApprovalTimeline（按 round 分组）+ act 操作区 | detail/{instanceId}、act | oa:approval:process:detail |
| 考勤规则 | 二 | 规则表单（workdays 多选、lunch 时段、IP 段）；已生效规则改版=新建版本 | attendance/rule/* | oa:attendance:rule:* |
| 考勤月报 | 二 | 按部门聚合（DataScope DEPT_TREE）；导出走队列+下载链接 | attendance/report/* | oa:attendance:report:* |
| 公告管理 | 三 | 富文本（XSS 过滤提示）、定时发布、已读统计 | announcement/* | oa:announcement:* |
| 文档中心 | 三 | 目录树、上传（白名单类型）、权限矩阵（view/upload/manage） | doc/* | oa:document:* |

## 2. mobile 移动端（unibest v4.4.1）

### 2.1 工程现状与约定

- 模板已就位：`src/pages/` 约定式路由、`src/layouts/default.vue`、**自定义 tabbar**（`src/tabbar/`）、
  **alova**（`@alova/adapter-uniapp`）请求客户端、`z-paging` 分页组件、UnoCSS、`pinia-plugin-persistedstate`。
- 页面新增只需在 `src/pages/` 建目录（文件即路由）；页面级配置用路由块注释（`vite-plugin-uni-pages`）。
- 待安装：`pnpm add wot-design-uni`（配置 easycom 按需导入）。

### 2.2 Tabbar 与页面清单

**Tabbar（4 个）**：工作台（index）｜审批（approval）｜消息（message）｜我的（me）

| 页面路径 | 阶段 | 核心交互 | 对应接口（D4） |
| --- | --- | --- | --- |
| pages/login/index | 一 | 账密 / 手机验证码（60s 冷却倒计时）；登录后按角色进工作台 | /api/v1/auth/*（sms/send、login） |
| pages/login/bind | 一 | 小程序：wx.login → 服务端 code2session → 首次绑定（验证码校验）→ mobile JWT | /api/v1/oa/auth/bind |
| pages/index/index | 一 | 工作台：待办数角标、快捷入口（发起/打卡/公告）、置顶公告轮播 | approval/todos、message/unread-count、announcement/list |
| pages/approval/templates | 一 | 可发起模板宫格（name+icon+bizType，缓存 5min） | approval/templates |
| pages/approval/create | 一 | DynamicForm 动态表单（按 templateId formSchema 渲染）+ 抄送人选择 → 提交 | approval/submit |
| pages/approval/mine | 一 | 我的申请列表（z-paging，按状态筛选；DRAFT 可编辑，REJECTED 可重提） | approval/list |
| pages/approval/todo | 一 | 待我审批列表（z-paging）→ 进详情处理 | approval/todos |
| pages/approval/detail | 一 | 详情：BizDataCard + 只读表单 + 时间线（含轮次）；底部操作：同意/驳回/转交/撤回 | approval/detail、act、cancel、resubmit |
| pages/approval/ccs | 一 | 抄送我的（只读详情复用 detail） | approval/ccs |
| pages/message/index | 一 | 消息盒子（bizType 分段、未读角标、点击跳转对应详情） | message/list、read、unread-count |
| pages/me/index | 一 | 用户信息、绑定状态、退出登录 | /api/v1/oa/auth/me |
| pages/attendance/punch | 二 | 打卡大按钮：同步写库成功才反馈；失败提示（IP 段/时间窗/重复打卡 duplicated 语义） | attendance/punch |
| pages/attendance/calendar | 二 | 月历逐日状态色标（历史已结算/当日暂计/未来为空）、迟到分钟明细 | attendance/calendar |
| pages/attendance/correct | 二 | 补卡提交（选日期+事由）→ 走审批实例 | attendance/correct/submit |
| pages/announcement/{list,detail} | 三 | 公告列表（置顶优先）/ 详情（服务端过滤后内容，进详情即写已读） | announcement/list、detail |
| pages/doc/{tree,list,view} | 三 | H5 只读：目录树 → 文件列表 → 预览(PDF)/下载（校验 view 权限） | doc/folder/tree、file/list、preview、download |

### 2.3 状态与公共逻辑

- **store**：`useUserStore`（access/refresh token、用户信息、持久化）；`useBadgeStore`（待办/未读角标，登录后拉取 + act 后刷新）。
- **请求拦截（alova）**：注入 `Authorization: Bearer`；**401 → refresh_token 换发并重放原请求，并发请求等待同一次刷新**（联调首日验证，D5 L1b）。
- **登录拦截**：路由拦截器维护白名单（login、announcement/detail 只读等），未登录跳 login。
- **双端差异**：H5 在微信内置浏览器运行（无 Web Push，站内消息+角标为保底）；小程序审批待办经 Outbox → 订阅消息（一次性授权，授权状态落库，未授权降级）。
