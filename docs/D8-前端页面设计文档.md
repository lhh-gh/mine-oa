# MineAdmin OA 系统 — 前端页面设计文档（D8）

> 版本：v0.5｜日期：2026-10-26
> 范围：MineAdmin/web（Vue3+Element Plus）和MineAdmin/mobile（unibest4.4.1）
> 依据：D1分期、D2身份/工程约定、D3数据快照、D4唯一接口契约；新增页面及接入均待实现

## 1. web后台与员工PC

### 1.1 模块结构与数据边界

```text
web/src/modules/oa/
├── api/                  # approval/employee/attendance/message/announcement/document.ts
├── views/
│   ├── approval/template/{index.vue,form.vue,data/}
│   ├── approval/process/{templates.vue,create.vue,mine.vue,todo.vue,done.vue,ccs.vue}
│   ├── approval/detail/index.vue
│   ├── employee/primary-department/{index.vue,form.vue,data/}
│   ├── message/index.vue
│   ├── attendance/{rule,report,correct}/
│   ├── announcement/
│   └── document/
├── components/           # LeaveBillForm、DynamicForm、NodeSchemaEditor、ApprovalTimeline、BizDataCard
└── locales/zh_CN[简体中文].yaml
```

内部员工使用SYSTEM100账号登录既有后台default场景，基础oa_employee角色只见自助页面，
不会因使用SYSTEM类别获得系统管理权限；审批处理权仍以当前待办处理人和流程状态为准。
HR/模板管理员授予附加角色；同一用户在移动端继续使用相同user_id，JWT场景独立。

业务API统一由useHttp封装，列表沿用现有base模块的useTable/表格请求配置；
分页输入转换为page/page_size，消费data.list/total，不另写pageSize或要求后端返回页码。
OA新增BIGINT字段使用string ID，当前原有后台passport/菜单契约保留，模块边界适配。
所有按钮使用具体v-auth/hasAuth权限；详情操作区以服务端allowedActions进一步限制。

固定请假字段来自billData（假别、起止、事由、附件）；DynamicForm仅渲染formData附加字段。
每轮详情读取round快照，不能用当前模板/当前单据还原旧轮次。日期、时长和金额等最终计算在服务端。

### 1.2 菜单与组件值（首个页面的确定配置）

`useRouteStore.ts`自行拼接 `../../modules/` 和后缀，菜单component只写相对模块路径：

```json
{
  "name":"oa:approval:template:list",
  "path":"/oa/approval/template",
  "component":"oa/views/approval/template/index",
  "meta":{
    "title":"审批模板",
    "type":"M",
    "componentPath":"modules/",
    "componentSuffix":".vue",
    "useDefaultLayout":true,
    "hidden":false
  },
  "status":1
}
```

component不加`modules/`前缀和`.vue`后缀；componentPath与componentSuffix另存。
菜单Seeder补齐父级、排序等框架字段；name与接口Permission.code保持一致。
详情页注册隐藏菜单/路由，组件`oa/views/approval/detail/index`、权限name为oa:approval:process:detail，
不因隐藏入口而免除后端授权。种子分别建立页面项与操作权限，D4每个具体权限码均有对应记录。

### 1.3 页面、接口与角色追踪

| 页面 | 阶段 | 主要交互/接口 | 基础角色及权限 |
| --- | --- | --- | --- |
| 固定请假模板列表/编辑 | 一 | D4模板list/detail/save/status；有限附加字段和顺序节点，version条件更新 | 模板管理员；D4 oa:approval:template各具体码 |
| 模板入口/发起/申请/待办/已办/抄送 | 一 | D4后台完整流程入口：templates、templates/{id}、submit/list/todos/dones/ccs | 员工；D4 oa:approval:process对应具体码 |
| 审批详情 | 一 | 轮次切换、BizDataCard、只读DynamicForm、时间线、act/cancel/resubmit | 员工有详情权限且为资源参与者 |
| 办公主部门历史 | 一 | D4 employee/primary-department/list/save；显式生效日期 | HR；oa:employee:department:list/save |
| 消息盒子 | 一 | list/read/unread-count；角标由请求结果更新 | 员工；oa:message:list/read/count |
| 考勤规则 | 二 | 不可变规则版本、部门适用区间、未来切换 | HR；oa:attendance:rule:list/detail/save |
| 月报与导出 | 二 | 申请范围/当前范围交集、导出任务状态与授权下载 | HR；oa:attendance:report:list/export |
| 补卡记录 | 二 | 审批及当前修正来源显示，原始卡只读 | HR；oa:attendance:correct:list |
| 公告管理 | 三 | list/detail/save/publish/read-stats/urge | 公告管理员；D4具体announcement码 |

员工基础角色还授予合法employee选择和单据附件上传/下载；模板管理员额外需要部门/角色选择权限，
不把这些系统范围选择接口无差别赋给普通员工。超级管理员不是默认业务审批人。
一阶段NodeSchemaEditor只编辑线性节点列表；拖拽表单设计器/BPMN流程画布为后续独立功能。

## 2. mobile（unibest4.4.1）

### 2.1 配置事实源和工程现状

当前登录API主链为 `src/api → src/http/http.ts → src/http/interceptor.ts → uni.request`，
alova是可选样例且有认证占位，本项目不迁移到该链路。
现有token/user store、路由与tabbar提供基础设施；OA字段适配、double模式和完整登录门禁仍需实现。

| 改动 | 唯一手改位置 | 不手改的生成物 |
| --- | --- | --- |
| 页面路径/标题/布局 | 对应.vue内definePage宏 | src/pages.json及路由声明 |
| 全局页面风格/easycom | pages.config.ts | src/pages.json |
| AppID/H5路由等平台配置 | manifest.config.ts | src/manifest.json |
| Tab列表 | src/tabbar/config.ts，供pages.config.ts引用 | pages.json的tabBar段 |
| 分包 | vite.config.ts的UniPages({subPackages}) | pages.json的subPackages段 |
| 组件及自动导入 | 源组件/hooks及其插件配置 | src/types下对应d.ts |

每页使用definePage，不用含糊的路由注释代替现有规范；平台差异使用条件编译。
待安装wot-design-uni，并在pages.config.ts的easycom.custom按其命名约定加入`^wd-(.*)`映射，
与现有fg-/z-paging规则共存，H5/小程序验证按需引入和体积。

### 2.2 固定四Tab与主包

| Tab | pagePath（无前导斜线） | 用途 |
| --- | --- | --- |
| 工作台 | pages/index/index | 待办/未读、按当前阶段开放快捷入口 |
| 审批 | pages/approval/index | 发起/申请/待办/已办/抄送入口 |
| 消息 | pages/message/index | 本人消息盒子 |

删除不使用的demo页面入口，避免首期引入无关包体。

### 2.4 认证与请求适配

- useTokenStore保存token与到期时间，useUserStore只保存资料/角色，useBadgeStore保存可重建的角标。
- API认证返回snake_case转换为现有token DTO驼峰字段；me.id→userId，OA ID类型同步为string。
- VITE_AUTH_MODE=double；请求拦截器统一注入Bearer，业务页面不手动拼token。
- http层统一识别HTTP401及业务code401，刷新端点使用独立调用避免自入队；并发等待一次刷新，原请求最多重放一次。
- 失败统一结束等待队列、清理用户/token/角标并跳登录；不保留悬空Promise或重复toast。
- 所有认证路径固定/api/v1/oa/auth；不继续使用模板样例/auth/login或/auth/refreshToken。
- 双token有效秒数由服务器提供；前端到期值用于交互，实际权限与会话状态由后端决定。
- 列表请求page/page_size，响应只解包一次data；下载按Content-Type区分二进制/业务错误。

### 2.5 登录门禁与跨端接缝

只允许login、bind及必要错误页免登录，公告详情不在白名单。路由拦截覆盖navigateTo/reLaunch/redirectTo/switchTab；
App启动/恢复和H5直接进入/前进后退走同一个会话门禁，保留合法的业务目标路径及round参数。
门禁先由token store取得有效会话或协调刷新，成功后加载me，再继续目标页面；绑定页必须有有效待绑定流程状态。
角色受限Tab已有逻辑与登录门禁串联，避免互相重定向循环；页面不重复判断凭据。

微信登录/订阅授权只在MP-WEIXIN分支；文件文档入口只在H5分支；服务端从不按客户端平台声明代替鉴权。
三阶段订阅授权在用户操作中发起，按templateKey上报结果；不把一次授权等同无限额度，失败/UNKNOWN以站内消息保底。
H5前三阶段不用Web Push，消息在登录/进入工作台/操作后及手动刷新时同步。

### 2.6 组件与公共逻辑

web使用Element Plus，mobile使用wot-design-uni；不跨工程直接复用Vue SFC。
两端共享D4 DTO、formSchema约定及服务端校验结果；纯字段映射/展示规则按相同样例核对，必要时再抽取版本化纯TS包。
先完成固定LeaveBillForm、只读快照渲染、ApprovalTimeline和BizDataCard；有限DynamicForm只承载附加字段。
模板字段定义、formData和billData分别处理，旧轮次始终消费对应快照。
